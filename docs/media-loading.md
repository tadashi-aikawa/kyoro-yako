# 音楽・動画の読み込み

本編は、開始操作後と面の切替で、その面の音楽・動画のダウンロード完了を確認します。

- 待機中は戦闘時計を進めず、読み込み画面を表示します。
- 次の1面分の圧縮素材をバックグラウンドで先読みします。
- 道中曲とボス曲は、面の開始前にまとめてデコードします。
    - 効果: ボス登場時に音楽の準備待ちを挟みません。
    - 例外: エンディング曲や、未準備の曲へ戻るリトライは、弾のない場面で準備します。
- 動画は取得済みのBlob URLで再生します。
    - 効果: 再生中にHTTPの追加取得を待つ必要がありません。

## 待機画面

- ゲージの上で、既存のフクロウ3コマを羽ばたかせます。
    - 時計: 戦闘時計と独立した経過時間で動きます。
    - 素材: ゲーム起動時に読み込むWebPを再利用します。新しい動画や画像は追加しません。
- 通常の待機画面にはゲージ、`Loading...`、Escの案内を表示します。
    - 非表示: 読み込み対象の説明、取得件数、上下の罫線。
- ゲージは取得済みのファイル数に応じて段階的に進みます。
    - 補足: 取得後の再生準備中は100%を保ちます。キャラクターはその間も動きます。

## 失敗時の操作

通信が15秒進まない場合は中止し、最大3回まで取得を試みます。

- 復旧しないときは、プレイヤーの選択を待ちます。
    - 読み込み直す
    - 未取得の音声・映像を省略して続ける
    - タイトルへ戻る
- 読み込み中のEscでもタイトルへ戻れます。
    - 注意: そのプレイの途中から再開はできません。
- 一度失敗した素材を永続的な失敗として扱いません。
    - 再試行: 失敗した取得や動画デコーダーを破棄して、取得し直します。
- 取得に成功しても動画を再生できない場合は、同じ選択画面へ戻します。
    - 待機: 再生準備と実再生中のバッファ待ちは15秒で失敗扱いにします。

## 保持範囲

| データ | 保持する範囲 |
| --- | --- |
| 圧縮された音楽・動画 | 現在の面と次の1面 |
| デコード済みBGM | 現在曲と次曲の最大2曲 |
| 動画の要素とBlob URL | 現在の面で使うもの |

- 今の面の圧縮データは、面を離れるまで保持します。
    - 理由: ボス戦からのリトライで、道中曲をネットワークなしに展開し直せるようにします。
- 旧曲はフェードアウトを終えてから再生ノードと参照を解放します。
- 面を離れると、不要な取得を中止して圧縮データと動画を解放します。
    - 手順: 動画の再生と準備を停止し、srcを外してからBlob URLを破棄します。
- 次面の先読みはファイル取得だけです。先の面の曲を戦闘中にデコードしません。
- 2曲分の音声データは48kHzで約140MBが目安です。
    - 条件: 圧縮データ、画像、動画デコーダー、ブラウザの一時領域は別です。実メモリの解放時期はブラウザのGCに依存します。
- タイトルの音楽とオープニングはタイトル表示中に先読みします。
    - 操作: 音声の再生許可は最初のキー入力で得ます。タイトルの音楽が取得できなくてもメニューは操作できます。

## 構成と検証

| ファイル | 責務 |
| --- | --- |
| `src/media-assets.ts` | 圧縮ファイルの取得、進捗、キャンセル、Blob URLの寿命 |
| `src/game-media.ts` | 面の素材一覧、準備待ち、再試行と省略、次面の先読み |
| `src/bgm.ts` | デコードの直列化、2曲の上限、フェード後の解放 |
| `src/movies.ts` | 取得済み動画の再生準備と解放、再生障害の通知 |
| `src/game.ts` | 待機中の時計停止と操作、既存のシーンへの復帰 |

`main.ts`で`GameMedia`を注入します。ゲームロジックだけを検証するテストでは注入を省けます。

- ユニットテストは、途中取得、切断、再試行、省略、キャンセル、オフラインのリトライ、面の繰り返しと保持数を検証します。
- 開発ビルドの`window.__owlery.state()`には、準備状況と保持量を含めます。
    - `mediaLoading`・`mediaFailed`: 準備待ちと選択待ち
    - `mediaFiles`・`mediaBytes`: 保持・取得中の圧縮データ
    - `bgmBuffers`・`bgmBytes`: 再生中・フェード中・待機中を含む音声データ
